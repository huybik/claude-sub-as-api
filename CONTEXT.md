# Claude local API

- Source: github.com/huybik/claude-sub-as-api; DEPLOY.md copies it to `~/.local/share/claude-local-api`. Node.js 22 built-ins (validated on 22.19.0), Claude Code on `PATH` (validated on 2.1.296; profile rotation and the early stop rely on the 2.1.304 `rate_limit_event` order: without it every messages call waits the one-second fallback), existing subscription logins.
- `server.mjs` owns HTTP and subprocesses; `anthropic.mjs` owns protocol translation; `queue.mjs` owns concurrency; `reuse.mjs` owns response reuse; `cloud.mjs` owns cloud sessions; `quota.mjs` owns per-profile quota and profile choice.
- Launcher: `~/.local/bin/claude-local-api`. LaunchAgent: `~/Library/LaunchAgents/local.claude-api.plist`; starts at login, restarts on exit.
- Bind `127.0.0.1:8787`; every endpoint requires `token` (0600) as Bearer or `x-api-key`.
- Models: Sonnet, Opus, and Haiku 5.5. All five effort levels. No model switching or paid API credential path (a proxy profile bills whatever its proxy's pool holds; a different model still fails). `x-local-backend` selects `local` (default) or experimental `cloud` on `/v1/messages`; never changes mode after a failure. `x-local-profile` selects a name from `profiles.json`, created on first start as `{"default": null}` when missing; without it the call rotates (below). `default` leaves `CLAUDE_CONFIG_DIR` unset. Any other name is an absolute config directory for that call, or a proxy object `{base_url, config_dir?}` (below). Cloud accepts only `default`. Every profile's subscription login is checked at startup (rotation may use any of them); names start with a letter so object order is file order. Safe mode still ignores that profile's settings.
- Cloud: requires `CLAUDE_LOCAL_API_CLOUD_ENVIRONMENT=env_...`, reads the existing Keychain/file OAuth login and calls the undocumented `/v1/code/sessions` API. One fresh session/one user turn, no repository/connectors, all tools denied, custom system/effort/images supported. Archive before delivery and on abort; report cleanup failures with the session URL. Transcript remains in the account. Only `max_tokens: 128000`: per-session env variables are disabled upstream. Reject history, tools, schemas and cache_control; cloud prompt caching is automatic. SSE is buffered until completion/archive. New-session seed replies omit user_message_uuid: require exactly the submitted user turn, excluding synthetic image replay records. Cloud counters are separate, and do not constitute a billing ledger; credits exhaustion follows account rules.
- Local `/v1/messages`: Anthropic SDK message lists, base64 images, client tools/results, SSE, output schema, effort, `cache_control` (message blocks, nested tool-result blocks, and top-level). Accept direct tool callers and empty SDK metadata (`caller`, `toolset_name`, `citations`). Merge adjacent roles before tool-result validation. Unsupported fields fail explicitly; see README and docs/reference.md limits.
- Text-only `system` turns are a local extension: append them to the top-level system prompt in encounter order. Send the combined prompt in SDK initialization with snapshots off. System priority is retained; inline positions are not.
- Preserve history with a temporary linked transcript and `--resume`. A final user message with tool results goes into the transcript whole, and `CLAUDE_CODE_RESUME_INTERRUPTED_TURN=1` continues that turn with no stdin prompt (Claude Code adds "Continue from where you left off."). A stdin prompt after transcript results made Claude Code insert a synthetic "No response requested." reply (2.1.296); stdin results get replaced as interrupted. Other final user content is structured, verbatim stdin input. Remove request files after completion.
- Prompt cache (2026-10-12): `DISABLE_PROMPT_CACHING=1` on `/v1/messages`, so only client breakpoints cache, with their own TTL and all four slots. Claude Code otherwise marked system (1–2), last assistant, and the closing environment note, all one-hour, and passed client marks through. It announces the account context (`session_context` attachment, email) before the first prompt a process sees; until it is known (once per profile and login; each call reads the login from `oauthAccount.emailAddress` in the profile's `.claude.json`, which Claude Code writes atomically, and a context learned while the login switched is dropped), a call runs with `--session-id` so `sessionContext()` reads that attachment from the profile's `projects` directory and deletes it; rebuilt histories insert it after the first message, so follow-ups match the first call's bytes. Without it, a tool continuation folds the announcement into the last tool result. Rechecked on Claude Code 2.1.302 (2026-10-18, capture proxy): one upstream request per call, image bytes unchanged, a follow-up byte-identical to the first call up to its mark. System and tool breakpoints return 400 (initialize takes system strings); top-level marks the last block; at most four, 1h before 5m. Haiku check: shared prefix, follow-up and tool-result turns read 97% of the prompt; live 8787 run (one writer, four parallel readers, one follow-up) read 81.4% of all input. Claude Code rebuilds stdin images (`maybeResizeAndDownsampleImageBlock`) as `{type, source}`, dropping their `cache_control`, so `prepareAnthropic` (local only, after validation's breakpoint checks) moves a breakpoint on an image of the final non-tool-result user message to the nearest earlier text, tool_use or tool_result block, across messages into the transcript (400 when none); measured 2026-10-16: 0 written/read before, the 38.7k-token prefix before the image after.
- Profile rotation (2026-10-20, ideas from KarpelesLab/teamclaude): Claude Code 2.1.304 writes a `rate_limit_event` per call (`status`, `resetsAt` seconds, `rateLimitType`, `isUsingOverage`, `unifiedWindows` with utilization), after `message_stop` on success and before the 429 result on a refusal; it sends one upstream request and does not retry Anthropic's quota 429 (it does retry a 429 with only a short `retry-after`, such as TeamClaude's). `quota.mjs` keeps reports per profile and login (a `/login` starts over; a late call on the old login can't touch the new one). Spent = `rejected` without extra usage, until `resetsAt`, and only the reset ends it: a call admitted before the limit can report `allowed` after it (review of PR #6). The newest-started call's report wins, so extra usage can't be undone by an older call; it lapses at the window's reset. `seven_day_opus`/`seven_day_sonnet` spend only that family; a profile whose login can't be read is skipped. No header: stay on the current profile (first in `profiles.json`) while it has plan quota, else the first in file order with plan quota, then one on paid extra usage; a refused call whose stream has not started retries on the next profile (bounded by the profile count); each move logs one line. A named profile never moves and fails with 429 + `retry-after` while spent, checked before the queue so it needn't wait for a slot (rotating calls too when all are spent). Streaming generate starts its SSE on `message_start` (a refused call sends none) so it can move as well. When no profile can take a call and none reported a reset, the first unreadable login's 502 is thrown instead of a 429. Saved generate sessions resume on their recorded profile. Reuse keys use `*` for rotating calls. No threshold rotation, spreading or hold-until-reset (TeamClaude has them): stickiness keeps caches warm and the pool spends one account at a time. Checked 2026-10-20 on port 8799 with `default` pointed at a fake 429 upstream: streaming and JSON calls moved to `claude-l`, a named spent profile failed fast without a process, generate sessions stayed on their profile. In-memory checks covered family caps, overage order, login change and all-spent. No stored tests.
- Proxy profiles (2026-10-20, for `teamclaude run`): `base_url` becomes the child's `ANTHROPIC_BASE_URL`, the way `teamclaude run --no-mitm` launches Claude Code (MITM mode only adds hosts the server never calls). Loopback `http` with a port, no userinfo/query/fragment, normalized to origin + path without a trailing slash: Claude Code sends the profile's OAuth token there (the refresh URL stays platform.claude.com). The path is kept (`/tc-acct/<account>` pin). Without `config_dir` the child uses `~/.claude`; Claude Code needs that login before it sends, and TeamClaude swaps in a pool token. The child gets `CLAUDE_CODE_MAX_RETRIES=1`: TeamClaude hops once on a 5xx/529, then leaves the next try to the client (0 failed every 529); Claude Code 2.1.304's default ten took 182 s on a closed port and 11 requests in 196 s on the pinned-account 429 (`retry-after: 5`), one retry takes ~2 s and 6.5 s. A down proxy is a 502 and does not rotate. Claude Code reports any 429 without `anthropic-ratelimit-unified-reset` as `rejected` with no `resetsAt`: from Anthropic that is request-scoped and holds nothing; on a proxy profile (TeamClaude's pool-spent 429 carries only `retry-after`) `quota.mjs` holds the profile a minute (`refusedUntil`, `/v1/health` scope `proxy_refusal`), set and cleared only by the newest-started call. Checked 2026-10-20: live on 8799 against TeamClaude 1.1.25 (two-account pool) - auth status stays `firstParty`, a 15.6K-token prefix written then read, the proxy's `rate_limit_event` recorded; fakes on 8794 - pool-spent rotation, fast named 429, 529 then 200 succeeds, pinned 429, closed port; in-memory quota ordering.
- Client tools use an in-process SDK MCP protocol over CLI stdin/stdout. Return the first complete model message; stop on the `rate_limit_event` that follows it (one-second fallback), before tool execution: Claude Code asks `can_use_tool`, which is never answered, before `message_stop` (checked 2026-10-20 with a fake tool-call upstream; latency unchanged at ~1.6 s). The caller executes tools and supplies results in the next request.
- `/v1/generate`: original prompt API, optional SSE/schema/effort and opt-in saved sessions. `sessions.json` records successful IDs/models; Claude owns transcripts.
- Default one active call per GiB of RAM (48 on the 48 GB M4 Pro; raised from 10 on 2026-10-13, a `claude -p` child measured ~250 MB RSS), `CLAUDE_LOCAL_API_CONCURRENCY` overrides; the waiting list is unbounded (finite work waits rather than 503). No concurrency 429s seen at 10 (all 429s were session/spend limits); a 50-call Haiku burst at 48 slots returned 50 × 200 in 7 s, median call 4.3 s (alone 4.7 s), children peaked at 10.2 GB. Serialize the same saved-session ID; admit independent calls to free slots even with locked sessions waiting. Upstream rate limits remain 429.
- Spawn and parse stdout once; keep slots until child close. The first stop decides the outcome, so a client closing after the captured message ends (including while waiting for its `rate_limit_event`) is not a failed process. Twenty-minute execution timeout (raised from five on 2026-10-12: long high-effort turns ran past five); disconnect cancels; SIGKILL after one-second termination grace. Limit buffered stderr to 64 KiB. The prompt endpoint uses temporary system files; Messages sends system text through stdin. Both schema inputs are capped at 64 KiB.
- Safe mode, no built-in tools, no user/project/local settings; remove inherited API/provider environment variables. Restrict each process to its requested model and disable fallback. Managed policy still applies. Explicit SDK MCP definitions are the only added tool surface.
- `/v1/models` keeps the custom list shape. `/v1/health` shows concurrency and `quota` (current profile, each profile's last `rate_limit_info` and spent scopes); `/v1/usage` reports generation processes, observed model messages, failed processes, reported tokens (also per profile), and local reuse counts since startup. Each failed or cancelled process logs one stderr line (time, profile, model, status, error up to 300 characters). Reused bodies keep original usage/IDs; counters count upstream work once.
- Reuse defaults on for non-streaming, stateless text/JSON requests (activated 2026-10-12; live default cache/sharing, explicit opt-out and streaming checks passed). `x-local-cache`: execution backend + profile + exact endpoint/body bytes, ten-minute TTL, 32 MiB serialized bytes, 1,024 entries, LRU eviction; memory only. `x-local-coalesce`: pending-call sharing, no waiter cap. Both act before queue admission. Set both headers to `false` for independent answers. Streaming, sessions, tools and non-text content bypass reuse; explicit `true` on unsupported requests is rejected; cache stores only successful end_turn responses. Each shared client cancels independently; the last disconnect cancels the work. Failures leave no reusable entry. Saved generate sessions record their profile and resume only on that profile.
