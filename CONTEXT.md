# Claude local API

- Source: github.com/huybik/claude-sub-as-api; DEPLOY.md copies it to `~/.local/share/claude-local-api`. Node.js 22 built-ins (validated on 22.19.0), Claude Code 2.1.296 on `PATH`, existing subscription login.
- `server.mjs` owns HTTP and subprocesses; `anthropic.mjs` owns protocol translation; `queue.mjs` owns concurrency; `reuse.mjs` owns response reuse; `cloud.mjs` owns cloud sessions.
- Launcher: `~/.local/bin/claude-local-api`. LaunchAgent: `~/Library/LaunchAgents/local.claude-api.plist`; starts at login, restarts on exit.
- Bind `127.0.0.1:8787`; every endpoint requires `token` (0600) as Bearer or `x-api-key`.
- Models: Sonnet, Opus, and Haiku 5.5. All five effort levels. No model switching or paid API credential path. `x-local-backend` selects `local` (default) or experimental `cloud` on `/v1/messages`; never changes mode after a failure.
- Cloud: requires `CLAUDE_LOCAL_API_CLOUD_ENVIRONMENT=env_...`, reads the existing Keychain/file OAuth login and calls the undocumented `/v1/code/sessions` API. One fresh session/one user turn, no repository/connectors, all tools denied, custom system/effort/images supported. Archive before delivery and on abort; report cleanup failures with the session URL. Transcript remains in the account. Only `max_tokens: 128000`: per-session env variables are disabled upstream. Reject history, tools, schemas and cache_control; cloud prompt caching is automatic. SSE is buffered until completion/archive. New-session seed replies omit user_message_uuid: require exactly the submitted user turn, excluding synthetic image replay records. Cloud counters are separate, and do not constitute a billing ledger; credits exhaustion follows account rules.
- Local `/v1/messages`: Anthropic SDK message lists, base64 images, client tools/results, SSE, output schema, effort, `cache_control` (message blocks, nested tool-result blocks, and top-level). Accept direct tool callers and empty SDK metadata (`caller`, `toolset_name`, `citations`). Merge adjacent roles before tool-result validation. Unsupported fields fail explicitly; see README and docs/reference.md limits.
- Text-only `system` turns are a local extension: append them to the top-level system prompt in encounter order. Send the combined prompt in SDK initialization with snapshots off. System priority is retained; inline positions are not.
- Preserve history with a temporary linked transcript and `--resume`. A final user message with tool results goes into the transcript whole, and `CLAUDE_CODE_RESUME_INTERRUPTED_TURN=1` continues that turn with no stdin prompt (Claude Code adds "Continue from where you left off."). A stdin prompt after transcript results made Claude Code insert a synthetic "No response requested." reply (2.1.296); stdin results get replaced as interrupted. Other final user content is structured, verbatim stdin input. Remove request files after completion.
- Prompt cache (2026-10-12): `DISABLE_PROMPT_CACHING=1` on `/v1/messages`, so only client breakpoints cache, with their own TTL and all four slots. Claude Code otherwise marked system (1–2), last assistant, and the closing environment note, all one-hour, and passed client marks through. It announces the account context (`session_context` attachment, email) before the first prompt a process sees; until it is known (once per server start), a call runs with `--session-id` so `sessionContext()` reads that attachment from the transcript and deletes it; rebuilt histories insert it after the first message, so follow-ups match the first call's bytes. Without it, a tool continuation folds the announcement into the last tool result. Restart after a login change. System and tool breakpoints return 400 (initialize takes system strings); top-level marks the last block; at most four, 1h before 5m. Haiku check: shared prefix, follow-up and tool-result turns read 97% of the prompt; live 8787 run (one writer, four parallel readers, one follow-up) read 81.4% of all input.
- Client tools use an in-process SDK MCP protocol over CLI stdin/stdout. Return the first complete model message; stop before tool execution. The caller executes tools and supplies results in the next request.
- `/v1/generate`: original prompt API, optional SSE/schema/effort and opt-in saved sessions. `sessions.json` records successful IDs/models; Claude owns transcripts.
- Default one active call per GiB of RAM (48 on the 48 GB M4 Pro; raised from 10 on 2026-10-13, a `claude -p` child measured ~250 MB RSS), `CLAUDE_LOCAL_API_CONCURRENCY` overrides; the waiting list is unbounded (finite work waits rather than 503). No concurrency 429s seen at 10 (all 429s were session/spend limits); a 50-call Haiku burst at 48 slots returned 50 × 200 in 7 s, median call 4.3 s (alone 4.7 s), children peaked at 10.2 GB. Serialize the same saved-session ID; admit independent calls to free slots even with locked sessions waiting. Upstream rate limits remain 429.
- Spawn and parse stdout once; keep slots until child close. The first stop decides the outcome, so a client closing after the captured message ends is not a failed process. Twenty-minute execution timeout (raised from five on 2026-10-12: long high-effort turns ran past five); disconnect cancels; SIGKILL after one-second termination grace. Limit buffered stderr to 64 KiB. The prompt endpoint uses temporary system files; Messages sends system text through stdin. Both schema inputs are capped at 64 KiB.
- Safe mode, no built-in tools, no user/project/local settings; remove inherited API/provider environment variables. Restrict each process to its requested model and disable fallback. Managed policy still applies. Explicit SDK MCP definitions are the only added tool surface.
- `/v1/models` keeps the custom list shape. `/v1/health` shows concurrency; `/v1/usage` reports generation processes, observed model messages, failed processes, reported tokens, and local reuse counts since startup. Neither reports quota. Reused bodies keep original usage/IDs; counters count upstream work once.
- Reuse defaults on for non-streaming, stateless text/JSON requests (activated 2026-10-12; live default cache/sharing, explicit opt-out and streaming checks passed). `x-local-cache`: execution backend + exact endpoint/body bytes, ten-minute TTL, 32 MiB serialized bytes, 1,024 entries, LRU eviction; memory only. `x-local-coalesce`: pending-call sharing, no waiter cap. Both act before queue admission. Set both headers to `false` for independent answers. Streaming, sessions, tools and non-text content bypass reuse; explicit `true` on unsupported requests is rejected; cache stores only successful end_turn responses. Each shared client cancels independently; the last disconnect cancels the work. Failures leave no reusable entry.
