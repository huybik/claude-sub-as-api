# Claude local API

- Source: github.com/huybik/claude-sub-as-api; DEPLOY.md copies it to `~/.local/share/claude-local-api`. Node.js 22 built-ins (validated on 22.19.0), Claude Code 2.1.296 on `PATH`, existing subscription login.
- `server.mjs` owns HTTP and subprocesses; `anthropic.mjs` owns protocol translation; `queue.mjs` owns concurrency; `reuse.mjs` owns response reuse.
- Launcher: `~/.local/bin/claude-local-api`. LaunchAgent: `~/Library/LaunchAgents/local.claude-api.plist`; starts at login, restarts on exit.
- Bind `127.0.0.1:8787`; every endpoint requires `token` (0600) as Bearer or `x-api-key`.
- Models: Sonnet, Opus, and Haiku 5.5. All five effort levels. No model switching or paid API credential path.
- `/v1/messages`: Anthropic SDK message lists, base64 images, client tools/results, SSE, output schema, effort. Accept direct tool callers and empty SDK metadata (`caller`, `toolset_name`, `citations`). Merge adjacent roles before tool-result validation. Unsupported fields fail explicitly; see README limits.
- Text-only `system` turns are a local extension: append them to the top-level system prompt in encounter order. Send the combined prompt in SDK initialization with snapshots off. System priority is retained; inline positions are not.
- Preserve history with a temporary linked transcript and `--resume`. Include final tool results in the transcript before resume; otherwise Claude repairs them as interrupted calls before stdin is read. Send remaining final user content as structured, verbatim input (empty text starts a result-only continuation). Remove request files after completion.
- Client tools use an in-process SDK MCP protocol over CLI stdin/stdout. Return the first complete model message; stop before tool execution. The caller executes tools and supplies results in the next request.
- `/v1/generate`: original prompt API, optional SSE/schema/effort and opt-in saved sessions. `sessions.json` records successful IDs/models; Claude owns transcripts.
- Default 10 active calls, 32 queued. Serialize the same saved-session ID; admit independent calls to free slots even with a full queue of locked sessions. Queue-full is 503, upstream rate limits remain 429.
- Spawn and parse stdout once; keep slots until child close. Twenty-minute execution timeout (raised from five on 2026-10-12: long high-effort turns ran past five); disconnect cancels; SIGKILL after one-second termination grace. Limit buffered stderr to 64 KiB. The prompt endpoint uses temporary system files; Messages sends system text through stdin. Both schema inputs are capped at 64 KiB.
- Safe mode, no built-in tools, no user/project/local settings; remove inherited API/provider environment variables. Restrict each process to its requested model and disable fallback. Managed policy still applies. Explicit SDK MCP definitions are the only added tool surface.
- `/v1/models` keeps the custom list shape. `/v1/health` shows concurrency; `/v1/usage` reports generation processes, observed model messages, failed processes, reported tokens, and local reuse counts since startup. Neither reports quota. Reused bodies keep original usage/IDs; counters count upstream work once.
- Reuse defaults on for non-streaming, stateless text/JSON requests (activated 2026-10-12; live default cache/sharing, explicit opt-out and streaming checks passed). `x-local-cache`: exact endpoint/body bytes, ten-minute TTL, 32 MiB serialized bytes, 1,024 entries, LRU eviction; memory only. `x-local-coalesce`: pending-call sharing, up to 32 extra waiters. Both act before queue admission. Set both headers to `false` for independent answers. Streaming, sessions, tools and non-text content bypass reuse; explicit `true` on unsupported requests is rejected; cache stores only successful end_turn responses. Each shared client cancels independently; the last disconnect cancels the work. Failures leave no reusable entry.

No stored tests.
